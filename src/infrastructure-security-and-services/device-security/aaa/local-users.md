
# Local Users and Privilege Levels

Cisco IOS XE supports a **local user database** for authenticating users and assigning administrative privileges without requiring an external AAA server.

Local users are commonly used for:

- Authenticating SSH and console logins.
- Providing fallback authentication when TACACS+ or RADIUS servers are unavailable.
- Assigning privilege levels to administrators.
- Supporting local EXEC authorization.

Cisco IOS XE also provides **16 privilege levels**, numbered 0 through 15, which determine which CLI commands users can execute.

Local authentication and privilege levels can be used independently of external AAA servers or alongside centralized TACACS+ and RADIUS authentication.

---

## Local User Configuration

Local users are configured with the `username` command.

```text
username <name> [privilege <level>] secret <password>
```

For example:

```text
R1(config)# username admin privilege 15 secret Cisco123
R1(config)# username operator privilege 1 secret Cisco456
```

| Parameter | Purpose |
|---|---|
| `<name>` | Username used for authentication |
| `privilege <level>` | Assigns a privilege level from 0 to 15 |
| `secret <password>` | Configures a hashed password |

If the privilege level is omitted, the user is assigned privilege level 1 by default.

For example:

```text
R1(config)# username admin secret Cisco123
```

This creates a local user with privilege level 1.

The configured privilege level can be used when an EXEC session is created, subject to the applicable AAA authorization configuration.

## Local Passwords and Secrets

Cisco IOS XE supports both `password` and `secret` for local usernames.

### Username Password

```text
R1(config)# username admin password Cisco123
```

The `password` keyword stores a password in a form that may be plaintext or reversibly encoded, depending on the configuration.

For example, with `service password-encryption`, the password is typically stored using Cisco Type 7 encoding:

```text
R1(config)# service password-encryption
R1(config)# username admin password Cisco123
```

Type 7 encoding is reversible and does not provide strong password protection.

### Username Secret

```text
R1(config)# username admin secret Cisco123
```

The `secret` keyword stores a password hash rather than a reversibly encoded password.

Common IOS XE secret types include:

| Type | Algorithm | Security |
|---|---|---|
| 5 | MD5-based hash | Legacy, weak |
| 8 | PBKDF2-SHA-256 | Stronger |
| 9 | scrypt | Stronger |

Type 8 and Type 9 are preferred over older Type 5 hashes where supported.

For example, to explicitly use a Type 9 secret on supported IOS XE platforms:

```text
R1(config)# username admin algorithm-type scrypt secret Cisco123
```

The resulting secret is stored as a Type 9 hash.

> The `secret` keyword is preferred over `password`. The exact hash type generated by `username ... secret` without an explicit algorithm depends on the IOS XE release and configuration.

## Local Authentication

The `local` authentication method instructs IOS XE to verify credentials against the local user database.

For example:

```text
R1(config)# aaa new-model
R1(config)# username admin privilege 15 secret Cisco123
R1(config)# aaa authentication login default local
```

When a user attempts to log in, the router checks the supplied username and password against its local database.

- If the credentials match, authentication succeeds.
- If the credentials do not match, authentication fails.

The `local` method can also be configured as a fallback after external AAA:

```text
R1(config)# aaa authentication login default group tacacs+ local
```

In this case, local authentication is attempted only if TACACS+ authentication returns an error, such as when all applicable TACACS+ servers are unavailable.

An explicit authentication rejection from TACACS+ does not trigger local fallback.

---

## `local` vs. `local-case`

IOS XE supports two local authentication methods:

| Method | Username Matching | Password Matching |
|---|---|---|
| `local` | Case-insensitive | Case-sensitive |
| `local-case` | Case-sensitive | Case-sensitive |

For example:

```text
R1(config)# username Admin secret Cisco123
R1(config)# aaa authentication login default local
```

With `local`, the username can be entered using different capitalization, such as `Admin` or `admin`.

With `local-case`:

```text
R1(config)# aaa authentication login default local-case
```

The username must match the configured capitalization.

In both cases, the password remains case-sensitive.

## Privilege Levels

Cisco IOS XE provides 16 privilege levels, numbered **0 through 15**.

By default, commands are primarily assigned to three levels:

| Level | Default Purpose |
|---|---|
| **0** | Basic commands such as `enable`, `disable`, `exit`, `help`, and `logout` |
| **1** | User EXEC commands |
| **2–14** | Available for custom privilege levels |
| **15** | Privileged EXEC and configuration commands |

Privilege levels are hierarchical.

A user operating at privilege level 15 can execute commands assigned to levels 0 through 15.

A user operating at privilege level 5 can execute commands assigned to levels 0 through 5, but not commands assigned to levels 6 through 15.

### User EXEC Mode

A user at privilege level 1 normally receives the user EXEC prompt:

```text
R1>
```

This level permits basic monitoring and troubleshooting commands.

For example:

```text
R1> show ip interface brief
```

Commands assigned to higher privilege levels are unavailable.

### Privileged EXEC Mode

A user at privilege level 15 receives the privileged EXEC prompt:

```text
R1#
```

This level normally permits unrestricted access to IOS XE CLI commands, including configuration mode.

For example:

```text
R1# configure terminal
R1(config)#
```

### Intermediate Privilege Levels

Levels 2 through 14 can be customized to provide access to selected commands.

For example, an operator might be assigned privilege level 5 and permitted to execute specific troubleshooting commands without receiving full administrative access.

## Assigning Privilege Levels to Users

Assign a privilege level when creating a local user:

```text
R1(config)# username admin privilege 15 secret Cisco123
R1(config)# username operator privilege 5 secret Cisco456
```

The configured privilege level determines the user's locally defined privilege.

However, the privilege level actually assigned to an EXEC session can also depend on AAA authorization.

For example:

```text
aaa authentication login default local
aaa authorization exec default local
```

With local EXEC authorization, IOS XE can use the locally configured privilege level when establishing the EXEC session.

An administrator configured with privilege level 15 can therefore enter privileged EXEC mode directly, without executing `enable`.

---

## Local Authentication vs. Local Authorization

Authentication and authorization are separate AAA functions.

Consider:

```text
username admin privilege 15 secret Cisco123
!
aaa authentication login default local
aaa authorization exec default local
```

The router performs two operations:

1. **Authentication:** Verifies the username and password against the local database.
2. **EXEC authorization:** Uses local authorization information, including the user's configured privilege level.

Now consider:

```text
username admin privilege 15 secret Cisco123
!
aaa authentication login default local
aaa authorization exec default group tacacs+ if-authenticated
```

If TACACS+ authorization is unavailable, `if-authenticated` authorizes the EXEC session because the user has already authenticated.

However, `if-authenticated` does not retrieve the locally configured privilege level.

Consequently, the user may receive privilege level 1 rather than the locally configured level 15.

| EXEC Authorization Method | Behavior |
|---|---|
| `local` | Uses local authorization information, including configured privilege levels |
| `group tacacs+` | Uses authorization attributes returned by TACACS+ |
| `if-authenticated` | Authorizes an already authenticated user without retrieving local privilege attributes |
| `none` | Allows the EXEC session without an authorization check |

> The privilege level assigned during login can depend on line configuration, AAA authorization, and attributes returned by external servers. Local username privilege levels are not necessarily the final EXEC privilege levels in every AAA configuration.

## The `enable` Command

Users can change their privilege level using the `enable` command, provided they are authorized to do so and can satisfy the configured authentication requirements.

By default, `enable` requests privilege level 15.

```text
R1> enable
Password:
R1#
```

Configure an enable secret:

```text
R1(config)# enable secret Cisco123
```

The enable secret is separate from local user secrets.

### Enabling a Specific Privilege Level

The `enable` command also accepts a privilege level:

```text
R1> enable 5
Password:
R1#
```

This requests privilege level 5 instead of level 15.

Configure a level-specific enable secret:

```text
R1(config)# enable secret level 5 Cisco456
```

The `enable` command does not always use the locally configured enable secret.

If AAA enable authentication is configured, its method list determines how the request is authenticated.

For example:

```text
R1(config)# aaa authentication enable default group tacacs+ enable
```

The router attempts enable authentication through TACACS+ first.

If that method returns an error, it falls back to the local enable password or secret.

## Customizing Command Privilege Levels

By default, configuration commands require privilege level 15.

The `privilege` command changes the minimum privilege level required to execute a CLI command.

General syntax:

```text
privilege <mode> level <level> <command>
```

For example:

```text
R1(config)# privilege exec level 5 show ip route
```

This assigns the specified command to privilege level 5.

A user at privilege level 5 or higher can execute it.

A user below privilege level 5 cannot execute it unless another applicable privilege rule permits access.

### Privilege Command Modes

| Mode | Purpose |
|---|---|
| `exec` | Changes privileges for EXEC commands |
| `configure` | Changes privileges for global configuration commands |
| `interface` | Changes privileges for interface configuration commands |
| `router` | Changes privileges for routing protocol configuration commands |
| `line` | Changes privileges for line configuration commands |

For example:

```text
R1(config)# privilege exec level 5 show ip route
R1(config)# privilege exec level 5 show ip ospf neighbor
```

Users operating at privilege level 5 can execute these commands.

### Removing a Custom Privilege Assignment

Use the `no` form to remove a custom command privilege assignment:

```text
R1(config)# no privilege exec level 5 show ip route
```

This removes the specified privilege customization.

> IOS XE privilege assignments operate through the CLI command parser. Changing the privilege of a command can also affect related command forms or parser keywords. Test the effective permissions rather than assuming that a privilege change grants access to only one exact command string.

## Default Privilege Level for a Line

A line can be configured with a default privilege level.

For example:

```text
R1(config)# line console 0
R1(config-line)# privilege level 15
```

This configures privilege level 15 as the default for sessions on that line, subject to applicable AAA authorization behavior.

A similar command can be used under VTY lines:

```text
R1(config)# line vty 0 4
R1(config-line)# privilege level 5
```

**Line privilege settings and username privilege settings are separate mechanisms.**

When EXEC authorization is enabled, the privilege level may be determined by the authorization result rather than the line's configured default.

## Verifying Privilege Levels

### `show privilege`

Display the current session's privilege level:

```text
R1# show privilege
Current privilege level is 15
```

This is the simplest way to verify the privilege level actually assigned to a session.

### `show running-config`

Display locally configured users:

```text
R1# show running-config | include ^username
```

Example:

```text
username admin privilege 15 secret 9 <hash>
username operator privilege 5 secret 9 <hash>
```

The displayed secret is hashed rather than plaintext.

### `show parser view`

IOS XE also supports **parser views**, which provide role-based CLI access control beyond traditional privilege levels.

Parser views can restrict access to individual commands without relying solely on hierarchical privilege levels.

Parser views are a separate CLI authorization mechanism and are not the primary focus of this AAA section.

---

## Key Points

- IOS XE supports a local user database for authentication and authorization.
- Configure local users with `username <name> privilege <level> secret <password>`.
- The default locally configured user privilege level is **1**.
- The `secret` keyword is preferred over `password` because it stores a password hash.
- Type 7 passwords are reversibly encoded, while Type 8 and Type 9 secrets use stronger password hashing algorithms.
- `local` performs case-insensitive username matching.
- `local-case` performs case-sensitive username matching.
- Passwords are case-sensitive with both methods.
- IOS XE supports **16 privilege levels**, numbered 0 through 15.
- Privilege levels **0, 1, and 15** have predefined command assignments; levels 2–14 can be customized.
- Higher privilege levels inherit access to commands assigned to lower levels.
- `aaa authorization exec ... local` can use locally configured privilege levels.
- `if-authenticated` does not retrieve privilege attributes from the local user database.
- `enable` requests privilege level 15 by default, and `enable <level>` requests a specific level.
- `privilege <mode> level <level> <command>` changes a command's required privilege level.
- `show privilege` displays the current EXEC privilege level.
